# Клиентское приложение «Современная защита»

Новый нативный Flutter-клиент, без WebView. Дизайн по предоставленному макету. Четыре вкладки: Главная, Дело, Документы, Сообщения. «Ещё» открывается через аватар.

## Запуск

Из этой папки:

```powershell
flutter pub get
flutter run -d emulator-5554
```

Для сборки с тем же окружением, что и сайт, выполните из корня репозитория `node scripts/sync-mobile-env.mjs`, затем из папки приложения:

```powershell
flutter run -d emulator-5554 --dart-define-from-file=config/supabase.public.json
```

`build-android.ps1` выполняет синхронизацию настроек автоматически. В JSON попадают только URL и публичный ключ; серверный секрет исключён. Источник — `.env` с обычным приоритетом файлов Next.js, включая `.env.local`, если он существует.

## Общий кабинет на сайте и телефоне

Сайт: `/account`, вход: `/login`. Один пользователь Supabase Auth связан с `clients.user_id`; сайт и приложение читают его дела из одной базы с RLS. Входить нужно одним email и паролем, при этом сессии браузера и телефона остаются независимыми. Данные не копируются между двумя базами.

На сайте и в приложении доступны Главная, Дело, Документы, Сообщения; «Ещё» — через аватар. Переписка использует общие `messages` и `post_case_message`. На сайте прочие данные обновляются через Realtime, при возвращении во вкладку и резервно раз в 30 секунд. В приложении кабинет обновляется при возвращении на экран и жестом обновления; чат имеет собственные Realtime и опрос.

Для появления дел нужна связанная карточка клиента и созданное дело. Отсутствие данных показывается как пустой кабинет. Проверка чтения API не заменяет проверку входа настоящим клиентским аккаунтом.

Подключён новый Supabase `dukqvwqxgwyadffmdeee`. Публичные параметры находятся в `lib/config.dart`. Для другого окружения передайте `--dart-define=SUPABASE_URL=... --dart-define=SUPABASE_PUBLISHABLE_KEY=...`. Секреты сервера и пароли базы в приложение не включаются.

## Что подключено

- Вход email/пароль и проверка клиентской карточки; сотрудник не допускается. Самостоятельной регистрации нет.
- Сессия в Android Keystore / iOS Keychain через `flutter_secure_storage`.
- Выбор дела, текущий этап и история, запросы документов и статусы последних версий.
- История чата с пагинацией, отправка через существующий RPC с ключом повторной отправки, Realtime и резервное обновление раз в 20 секунд.
- Опубликованные условия и сохранение согласий через RPC.
- Профиль, график и подтверждённые оплаты, уведомления, опубликованные FAQ и контакты.
- Восстановление пароля: Android/iOS scheme `kz.modernsecure.client://auth/recovery`; адрес добавлен в Supabase Auth Redirect URLs.

Все запросы выполняются с пользовательской сессией и RLS. Тестовые имена/дела используются только в `test/render_test.dart`, не в приложении и не в Supabase. Если карточки клиента или дела нет, приложение показывает соответствующее состояние.

## Оставшиеся ограничения

- Загрузка и скачивание защищённых файлов пока не подключены. Существующий сервер сайта проверяет файлы и использует серверные Storage-права; нативному клиенту нужен отдельный защищённый обработчик. Экран документа сообщает об этом. Файлы не помечаются проверенными без проверки.
- Нет вложений чата, push-уведомлений, редактирования профиля и ответов на задачи из этого клиента. Уведомления пока доступны как список.
- Получение письма восстановления и вход реальным клиентом требуют проверки владельцем аккаунта. Пароли существующих пользователей не извлекались и не менялись.
- iOS-проект подготовлен, но сборка и проверка на iPhone требуют macOS/Xcode и подписи. APK debug предназначен для проверки, не для публикации в магазине.
- Текущий Supabase облачный, в Сингапуре; требование отдельного ТЗ о размещении в Казахстане этой работой не выполнено.

## Проверки

```powershell
flutter analyze
flutter test test/client_test.dart
flutter test test/render_test.dart --update-goldens
flutter build apk --debug
```

Если Windows/CMake не собирает проект из пути с кириллицей, запустите `./build-android.ps1`. Скрипт копирует исходники во временный ASCII-путь и возвращает debug APK для ARM64-телефона и x64-эмулятора в `build/app/outputs/flutter-apk/app-debug.apk`. Проверка на реальном устройстве выполняется отдельно.

Проверка нового backend из корня репозитория: `node scripts/check-mobile-backend.mjs`. Она не меняет данные и проверяет Auth и отсутствие выдачи данных анонимному клиенту.

Документация SDK: [Supabase Flutter](https://supabase.com/docs/reference/dart/initializing).
